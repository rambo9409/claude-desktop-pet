# 战斗循环助手 V2.6

## 使用流程

从右键“工具”打开战斗循环助手。可直接手动填写四个角色，也可先选推荐配队，再替换示例面板与倍率。截图入口可选择本地图片或粘贴剪贴板截图，识别结果先预览，再应用到指定角色；无法识别的字段保留原值，仍可手动修改。

推荐目录是随软件发布的离线快照，游戏版本标记为7.1，核验日期2026-10-29。目录包括三套Vesna星辉扩散、两套菲林斯月感电、奈芙尔爱诺月绽放、丝柯克冰水，以及那维莱特、阿蕾奇诺、雷电国家队，共10套。它是可练习的攻略集合，不是全队伍强度排行榜。每套显示适用范围、手法依据、充能说明和来源链接。来源及核验方法见 [配队数据说明](combat-data-sources.md)。

动作记号：E为元素战技，长E为长按战技，Q为元素爆发，Nx为x段普攻，C/CA为重击，D为冲刺取消。菲林斯短Q与常规Q不同；丝柯克使用特殊资源。不能仅按“Q键相同”套用通用能量模型。

## 输入与输出

角色可填写名字、元素、职责、攻击/生命/防御缩放、主要属性、双暴、伤害加成、充能、技能总倍率、冷却、能量、驻场时间、全队增伤与持续时间。敌人区填写等级、抗性、防御降低和简化增幅反应覆盖。

所有面板和倍率初值都只是通用示例，选择真实角色名不会自动获得真实天赋、武器、圣遗物或命座数据。截图只能提取可见面板文字，不能推断天赋总倍率、武器特效、命座、后台增益或完整循环。

输入错误一次列出并标记对应字段。可估算的配队会显示当前/参考属性后的循环总伤害及每秒伤害；参考属性线按职责设置，不是具体角色的毕业线。推荐配队的手法与通用模型按职责生成的步骤分别显示，避免把简单排序误称为角色专属最优连段。

## 计算边界

基本形式是 `主要属性 × 总倍率 × 增伤 × 期望暴击 × 防御 × 抗性 × 简化增幅反应`。重复E受冷却与可用动作时间限制；增益按持续时间折算平均覆盖，并包括释放者自身。仍未逐帧模拟附着、反应归属、快照、命座、专属资源和独立乘区。全队统一反应覆盖只是一项粗略假设，不能给雷水角色也套火系蒸发倍率。

`SupportsEstimate=false` 的预设仅显示手法，不展示伤害数字：Vesna、菲林斯、奈芙尔和丝柯克共7套。那维莱特、阿蕾奇诺、雷国的3套也只允许用手填参数做直伤粗估，不等于整队实战DPS。需要逐击精确评估时，参考 [gcsim](https://docs.gcsim.app/)；具体配装优化可使用 [Genshin Optimizer](https://github.com/frzyc/genshin-optimizer)。本工具没有嵌入或调用这些引擎。

## 文件与扩展接口

| 文件 | 职责 |
| --- | --- |
| `src/CombatPlannerModel.cs` | 输入、字段验证、粗算、存档 |
| `src/GenshinCombatPlanner.cs` | WPF界面、字段标记、导入预览与结果 |
| `src/GenshinCombatPlannerIntegration.cs` | 桌宠菜单与工具窗口入口 |
| `src/CombatPanelOcr.cs` | `ICombatPanelImageExtractor`、Windows本机OCR和面板文字解析 |
| `src/CombatPlannerPresets.cs` | 目录验证、加载、应用和链接验证 |
| `assets/combat-teams.json` | 内嵌推荐配队与来源，格式版本2 |
| `src/PetStorage.cs` | 原子文件写入、损坏备份与诊断 |

面板识别扩展点返回 `PanelStatReading`，缺失值用空值表示；后续可实现其他图像识别器。当前仅使用本机Windows识别，不需要云端密钥，截图不上传，也不读取游戏内存、修改游戏文件或自动按键。新增远程识别器时要显式说明图片发送目的地，不能把本机接口的存在说成已接入云端。

## 存档与更新

配队存档为 `%LocalAppData%\KoloPet\combat-plan.json`。损坏数据先备份再使用示例；备份失败时禁止悄悄覆盖。保存采用同目录临时文件再替换。问题记录在 `diagnostics.log`。

推荐目录内嵌为 `combat-teams.json` 资源。可放置同名文件到 `%LocalAppData%\KoloPet` 作为本地覆盖，只有格式验证通过且 `updated` 不早于内嵌日期才使用。格式版本2要求每队四人、唯一id、日期、适用范围、手法依据、HTTPS来源；`supportsEstimate` 缺失时默认关闭估算。旧格式或错误目录会回退内置并记录原因。覆盖文件不会自动下载或自动获得可信身份。

更新推荐时应先核验官方游戏版本，再查攻略原文；保留各攻略自身适用版本，不能把今天查看过的旧攻略称为今天的新结论。补充来源时只写必要的转述，保留原始链接。

## 验证

在项目根目录运行 `test.cmd -Suite CombatPlanner`。编译与总体回归结果以本次 `artifacts/tests/latest-run.json` 和发布验证记录为准。本说明描述功能和限制，不用历史测试结果冒充当前通过状态。
