# V2.7 角色拥有表与资料更新

这版把角色名单、配队攻略和计算模型分开。未来新增角色后，面板手填和截图识别仍可使用；增加有来源的配队通常只需更新JSON。新反应、特殊资源或缩放公式如果超出模型能力，需要改代码并验证，不能因为姓名已经出现在名单中就显示伤害估算。

## 使用顺序

1. 战斗循环助手 → **我的角色**，搜索并勾选拥有的角色，点击**保存拥有表并推荐**。搜索支持名称与已收录的中英文别名。
2. 找不到的角色可以输入名字后**添加并勾选**。旅行者各元素单独选择，拥有旅行者不自动表示已解锁冰或其他元素。
3. **只看已拥有角色能组出的队伍**默认选中。首次尚未设置拥有表时仍可浏览全部资料，并提示先设置；保存为空的拥有表表示没有勾选任何角色，不能视为全角色都有。
4. 关闭筛选可看缺员队，界面列出缺少的成员；缺员队可浏览手法，不能直接作为可用队载入。优先按缺员人数排列，同一人数沿用目录顺序，不代表伤害排名。
5. 成员齐全后仍需核对卡片里的命座、装备、充能及操作条件。当前拥有表只保存角色名字，不自动判断养成程度。

名单编辑支持批量勾选/取消当前搜索结果、清空全部勾选。点击取消不保存编辑；搜索本身不会删掉其他已勾选角色。拥有表保存于 `%LocalAppData%\KoloPet\combat-roster-owned.json`，与面板存档分开。

**匹配范围是资料库中已收录的完整四人攻略。** 没匹配不说明这些角色无法组队。系统不会随意拿另一位同元素角色替换缺员，也不会让未来角色套用薇斯娜或旧队的连段。

## 名单来源和覆盖

`assets/combat-roster.json` 提供127个基础条目：120个角色名字和7个独立元素的旅行者形态。旅行者男女合并到同一元素，元素之间不互相设别名。基础名单与当前配队成员、已保存的手动角色取并集，因此可在版本更新时继续补入。

角色名来自 Genshin Optimizer 维护者词典的固定提交 `c3586033db8a0e1717b494cfd845a87cf9ae79ec`，于2026-10-29核对：[简体中文](https://github.com/frzyc/genshin-optimizer/blob/c3586033db8a0e1717b494cfd845a87cf9ae79ec/libs/gi/dm-localization/assets/locales/chs/charNames_gen.json)、[英文](https://github.com/frzyc/genshin-optimizer/blob/c3586033db8a0e1717b494cfd845a87cf9ae79ec/libs/gi/dm-localization/assets/locales/en/charNames_gen.json)。这是维护者名称快照，**不是官方实时实装名册，不保证未来全角色完整**。来源中未译且当前攻略未引用的 `Somnia` 条目暂不纳入。

为兼容已有目录，Vesna、Odette、Vodyanitsa保留原有内部名称，中文列为别名；用户使用的“薇斯娜”与来源拼写“薇斯纳”均能匹配Vesna。旧目录的“法露珊”与标准名“珐露珊”合并匹配。别名只用于同一角色，不借此伪造阵容替换关系。

基础名单文件格式为 `Version: 1`、`Updated`、`Notice`、`Sources` 和 `Characters`；每个角色包含 `Name` 与 `Aliases`。更新内置基础名单需要重建发布，临时新增名字不需要：可手动添加，也可通过新配队目录自动补入。

## 更新攻略，不必重编译

在助手中点击**导入配队资料**选择JSON。程序先检查完整性及日期，再原子写入 `%LocalAppData%\KoloPet\combat-teams.json`，成功后更新候选和版本说明。**重新加载资料**重新读取这份本地覆盖资料；它不是联网检查按钮。

- 导入文件是**完整目录替换**，不是追加一个队伍。维护者应在旧目录基础上保留仍有效的队伍，再加入新队。
- 格式版本必须为 `version: 2`。`gameVersion`写适用游戏版本，`updated`采用 `yyyy-MM-dd`。日期早于当前生效目录时拒绝导入，同日修订允许；不能单纯改日期把旧攻略伪装成新核验。
- 每队必须有唯一 `id`、名字、恰好四个不重复成员、手法步骤、HTTPS来源、核对日期、适用范围和手法依据。成员名按别名归一后也不能重复。
- 单份资料最多512KB、500套。文件解析失败或写入失败保留原有目录；旧有效覆盖会备份到 `combat-teams.json.previous.json`。损坏旧覆盖在新导入前先备份，备份失败则停止替换。
- 本地覆盖无效或比内置旧时回退内置，诊断写入 `diagnostics.log`；文件不会被悄悄删掉。需要恢复内置时先退出程序，备份并移走本地 `combat-teams.json`，再重新启动。
- 更新配队目录不会清空拥有表或当前面板。已载入的队伍保留原参考和机制限制，需重新载入才换成新目录的成员与说明。
- 若新目录移除了已保存配队，重启后会保留输入并提示“已保存的配队资料已失效”，阻止直接伤害粗算。可导回包含该队的资料，或明确点击**转为自定义（保留输入）**后重新生成；通用估算仍不包含特殊机制。

维护时以仓库 [combat-teams.json](../assets/combat-teams.json) 为完整格式示例。关键字段如下：

| 字段 | 内容与约束 |
| --- | --- |
| `id` | 稳定的队伍标识；不能用同一个id偷偷替换成无关阵容 |
| `members` | 四人名字、职责、元素、基值类型及注意事项 |
| `role` | `main`、`offfield`、`support`、`sustain`之一 |
| `scaling` | 当前只支持 `attack`、`health`、`defense`；精通或复合缩放不能冒充已实现 |
| `rotation`、`energy`、`tips` | 操作顺序、供能建议、命座/装备等条件 |
| `sources` | 来源标题和直接支持这队成员/手法的HTTPS链接 |
| `verifiedAt`、`versionScope` | 实际核对日期及适用范围；旧队不包装成当期排行榜 |
| `rotationBasis` | 来源给出的轮转或经过哪些简化；自行编排必须明确说明 |
| `supportsEstimate`、`modelNote` | 模型是否可估算及遗漏；不支持的机制设为false，只提供手法 |

导入校验只检查格式、链接类型、日期和必要内容，不能证明攻略正确或来源可信。资料维护者仍应核实四人组合、轮转、条件和游戏版本。新增特殊机制默认“仅手法”，经实现与专门测试后才可开放估算。

内置共14套。原10套的来源和核验方式见[配队资料来源](combat-data-sources.md)。新增4套补充只拥有旧角色的用户，均标“经典队参考”，没有进行当期强度排名；均设置 `supportsEstimate: false`。

| 砂糖、行秋、菲谢尔、北斗 | [KQM砂糖速查](https://keqingmains.com/q/sucrose-quickguide/)感电四人例；省略部分穿插攻击，保留奥兹接续与砂糖普攻驱动 |
